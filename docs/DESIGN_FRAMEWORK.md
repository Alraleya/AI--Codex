# 产品设计框架

## 1. 产品定位

工作台不是生产控制器，而是本地剧集观察台：

- Codex 负责与用户协作、理解创意和发起制作。
- 确定性状态机负责依赖、校验、状态和资产落盘。
- 工作台负责项目/剧集导航、全流程展示、产物预览和标注。

这个边界让用户把创作对话留在 Codex，把页面留给高密度视觉检查。

## 2. 信息架构

### 项目首页

- 项目列表：从 `workspace/projects/*/project.json` 读取。
- 剧集列表：从对应 `status/*.json` 和 `episode.json` 组合。
- 卡片字段：名称、主题、运行状态、进度、风格、时长、镜头数、更新时间和待处理标注数。

### 剧集页

- 剧集概要：主题、钩子、风格、总时长、画幅、镜头数和整体进度。
- 九阶段导航：完整显示所有节点，点击只切换查看内容。
- 产物区：只展示状态机登记的活跃资产。
- 标注区：分开“添加建议”和“要求重做”，支持阶段级或资产级文本反馈。
- 活动区：显示最近状态机事件与错误。

### 产物职责分工

故事板与定妆图不是同一种参考物，必须保持职责分离：

- 灰度故事板是导演动作预演，负责构图、景别、人物姿态、动作状态、屏幕方向、空间关系、道具接触、受力方向、运动轨迹和英雄帧。
- 角色定妆图是人物身份权威，负责脸型、发型、服装、比例、胡须、眼镜和其他跨镜头识别特征。
- 场景定妆图是环境权威，负责空间几何、材质、基础光线和固定环境锚点。
- 道具定妆图是关键道具权威，负责外观、材质、尺寸感和需要跨镜头保持的状态特征。
- 视频 Prompt 在第一阶段与剧本和分镜一起锁定；故事板和定妆图不能反向改写正文。
- 第二阶段的资源规划决定每个生成单元允许绑定哪些参考图以及它们是否必需。第七阶段最多绑定8张已通过资产，只写独立 JSON 清单和 Prompt SHA-256。

故事板出图按视频生成单元绑定定妆参考：每个单元只读取 `asset_plan.json` 中声明且成功产出的资产。必需资产缺失会阻塞，可选资产缺失会记录 omitted 并跳过；未规划资产禁止临时加入。P01 是生成单元本地起始状态，内部镜头与硬切保持第一阶段设计。各单元故事板可独立并行生成，整组完成后执行一次忠实度审查；审查只能要求重做故事板，不能修改剧本、分镜或视频 Prompt。

故事板底图采用黑白或灰度导演草稿，不承担完整色彩和最终渲染质量。定妆图负责具体色彩、材质、光线和身份细节，避免模型在故事板与定妆图之间争夺同一职责。

故事板允许使用少量、固定含义的彩色控制标记。标记只表示导演指令，不属于场景内容，也不进入最终视频：

- 青色实线箭头：运动轨迹。
- 黄色虚线：视线方向。
- 红色圆圈：真实接触点。
- 红色箭头：受力方向。
- 紫色小星标：英雄帧或动作短暂停顿。

控制标记必须稀疏、局部、无文字图例；故事板 Prompt 必须说明其含义，并要求视频模型将标记转换为自然连续的动作。最终视频不得出现箭头、虚线、圆圈、星标、草稿线、网格、标签或其他导演标记。

故事板和控制标记必须执行第一阶段锁定内容。下游不存在重写视频 Prompt 的阶段；视频调用原样读取第一阶段正文和独立参考绑定清单。

## 3. 交互原则

- 页面没有生产按钮，避免出现两个调度中枢。
- 页面每 4–5 秒轮询本地状态，刷新后可恢复。
- 空产物明确显示为空，不用视觉占位冒充文件。
- 图片和视频直接预览；文本与 Prompt 使用阅读器。
- 新标注只记录人的意图，不执行 Provider 或推进 Stage；`redo` 会把对应 Task 标为 `redo_requested`。

## 4. 标注模型

标注支持两种目标：

- 阶段级：对一个阶段的整体结果提出反馈。
- 资产级：针对某个文档、Prompt、图片或视频反馈。

`status.json` 只保存：

- `latest_revision`
- `handled_revision`
- `pending_count`
- `redo_count`
- `manifest_path`
- `updated_at`

正文按单条 JSON 文件保存。Codex 只有发现 `pending_count > 0` 时才读取未处理内容。

核心关系为 `Episode → Stage → Task → Asset Revision → Annotation`。标注生命周期为：

```text
open → planned → processing → verifying → resolved
```

`dismissed` 与 `superseded` 是明确记录原因的终态。`redo` 必须经过 Repair Plan；生成成功不等于解决，真实文件与合同校验及整组 Barrier Review 通过后才能关闭。

后续如果确有价值，再增加图片坐标、框选和涂鸦，不在初版建立复杂画布。

## 5. 视觉原则

- 暗色电影工作台基调。
- 蓝紫表示系统与选中状态。
- 绿色表示完成，橙色表示运行或待处理，红色表示阻塞。
- 信息密度优先于装饰动效。
- 窄屏下项目列表横向滚动，产物与标注改为单列。
- 故事板预览显示灰度导演草稿与少量彩色控制标记；定妆图保留完整色彩、材质和光线信息。
- 工作台应让用户能区分“动作参考”和“身份/环境参考”，不把灰度故事板误认为角色定妆或场景定妆。
- 故事板生成记录每个镜头实际使用的参考清单，便于复核人物一致性和定位错误参考造成的漂移。

## 6. 明确不出现的内容

- 新建项目或剧集表单。
- AI 创意顾问面板。
- 继续、暂停、重跑和确认视频按钮。
- 模型、Provider 或 runner 选择器。
- 任意节点推进、回滚或假历史版本。
- Mock、Dry-run 或假资产入口。
